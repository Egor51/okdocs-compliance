# Детальные причины `FAILED`

## Назначение

Терминальный `FAILED` содержит машинно-читаемую причину в поле `failure`. Технические сообщения
исключений и имена Java-классов наружу не передаются. Старое поле `errorMessage` временно сохраняется
как безопасный fallback для клиентов предыдущей версии.

```json
{
  "status": "FAILED",
  "errorMessage": "Сайт не завершил защищённое соединение вовремя",
  "failure": {
    "code": "TLS_HANDSHAKE_TIMEOUT",
    "stage": "TLS",
    "retryable": true,
    "httpStatus": null,
    "fetchMode": "HTTP",
    "fallbackAttempted": false,
    "incidentId": null
  }
}
```

Поле добавлено в `ScanStatusResponse`, `ScanFailedEvent` (schema version 2) и `MonitorRunDto`.
Оно nullable для чтения старых строк и событий. Клиенты обязаны принимать неизвестные будущие
значения `code` и `stage` как `UNKNOWN`.

## Политика классификации

- `code` — устойчивая причина для UI, метрик и аналитики.
- `stage` — этап, на котором проверка остановилась.
- `retryable` — подсказка о временном характере причины, а не команда автоматического повтора.
- `httpStatus` заполняется только после получения корректного HTTP status line.
- `fetchMode` различает HTTP и browser/CDP.
- `fallbackAttempted` зарезервирован для управляемого browser/region fallback.
- `incidentId` создаётся для непредвиденной внутренней ошибки и связывает ответ с логами.

Причина стартовой страницы имеет приоритет над результатами вторичных URL: успешный ответ
`/privacy` не может превратить недоступную главную страницу в успешный скан. Ошибки priority hints
не становятся терминальной причиной, если главная страница успешно обработана.

## Таймауты и владение обработкой

`PinnedHttpFetcher` отдельно ограничивает TCP connect, TLS handshake и чтение ответа, при этом
каждая страница также ограничена единым deadline. Пул static crawler workers принудительно
останавливается по deadline.

Kafka consumer атомарно захватывает скан переходом `QUEUED → CRAWLING`. Повторная доставка для
`CRAWLING` или `ANALYZING` подтверждается без нового запуска. Если владелец погиб, reaper завершает
скан с `PIPELINE_TIMEOUT`; он не подменяет первичную причину уже завершённого скана.

## Региональная доступность

`TLS_HANDSHAKE_TIMEOUT` с российской точки сам по себе не доказывает геоблокировку. Пользовательский
текст допускает обе причины: сайт недоступен из региона проверки или не завершил TLS-соединение.

Проверка через зарубежную точку — отдельное расширение. Для неё контракт уже содержит
`fallbackAttempted` и `fetchMode`, но корректная реализация должна также фиксировать исходный и
fallback-регионы и не выдавать зарубежную доступность за доступность для пользователей из РФ.
